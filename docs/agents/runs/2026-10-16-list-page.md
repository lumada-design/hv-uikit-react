# List page run — 2026-10-16

Delivery check for the story "Design rules, metadata and tooling architecture"
(continues HVUIKIT-7481). Compared against the off-system choices found in the
HVUIKIT-7482 spike and the baseline harness on `spike/hvuikit-7481-component-context`.

**n = 1 per arm.** One task, one model, one generation each. Read it as a smoke
test of the delivery path, not a measurement.

## Setup

- Consumer app **outside the repo**, installing `@pentaho/uikit-react-core` and
  `@pentaho/uikit-tools` from `npm pack` tarballs of this branch, plus
  `npx uikit-tools init --host claude`.
- Same task for both arms (Claude Sonnet, fresh context, told to stay in the app
  directory): a `DatasetsPage` listing datasets from a mock API
  (dates are ISO strings), with name, owner, status, last
  updated, pagination, create and delete. `tsc` must pass.
- **With context:** the guide and `AGENTS.md` in context (as `CLAUDE.md` imports
  them), the `build-list-page` skill available, lookups and checks runnable.
- **No context:** nothing but the task; no `node_modules` reading.

The two generated pages are attached to the pull request rather than kept in the repo.

## Result

Mechanical checks do not tell the arms apart:

| Check                        | With context | No context |
| ---------------------------- | ------------ | ---------- |
| `tsc`                        | pass         | pass       |
| `uikit-tools validate`       | 0            | 0          |
| baseline scorer (`score.ts`) | 0            | 0          |

The differences are all in `checked` rules that have no check yet, reviewed by hand:

| Rule (7482 finding)                                 | With context                                                                             | No context                                                            |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `destructive/confirm` ("Warning" dialog for delete) | Plain `HvDialog`, title names the item, `negativeGhost` confirm, `secondaryGhost` cancel | Deletes immediately from the row button; no confirmation              |
| `date/format` (broken ISO dates)                    | `Intl.DateTimeFormat` with the user's locale                                             | `toLocaleString` — acceptable                                         |
| `layout/page` (`HvGlobalActions` without padding)   | `HvGlobalActions` with the create action, inside `flex flex-col gap-md p-md`             | No `HvGlobalActions`; loose title and button, no page padding or gaps |
| `components/prefer` (tags without `HvTag`)          | `HvTag type="semantic"` for status                                                       | Status as raw text                                                    |
| `status/semantic-color`                             | positive / warning / negative with labels                                                | —                                                                     |
| `data/states`                                       | Skeleton on first load, `HvEmptyState` for empty and error with actions                  | Error text, "No datasets found" table row, no loading UI              |
| `HvTable/section`, table name                       | `HvTableSection`, `aria-label`                                                           | Neither                                                               |

Cost: with context 85.5k tokens, 9 tool calls, 64 s; no context 64k tokens,
5 tool calls, 31 s.

## What the run found, and what changed because of it

Fixed on this branch:

- **Parts had no lookups.** `HvTableSection` and other parts the rules require
  returned "No guidance". Parts named by a contract now get a props-only entry
  (20 parts).
- **`HvEmptyState` contract said `icon` is optional**; the type requires it. Fixed
  in the contract and in the `data/states` example.
- **`data/states` example** used a text skeleton without `role`/`aria-label`,
  contradicting `HvSkeleton`'s own a11y notes. Fixed.

Open, for follow-up stories:

- **Checks do not cover the `checked` rules.** Every difference above is invisible
  to `validate` and to the baseline scorer. Writing those checks (AST-based, on
  the baseline scorer's engine) is what turns this into a measurable result.
- **Rule and contract examples are not type-checked.** The `icon` mismatch would
  have failed a build that compiles the Do examples.
- **Hooks have no lookups** (`useHvTable`, `useHvPagination`), though table rules
  point at them.
- **Page-change loading** is not covered: `data/states` mentions
  `HvLoadingContainer`, but the run only handled the first load.
