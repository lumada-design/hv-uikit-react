# Working with AI

**UI Kit** gives your AI coding agent what it needs to build with UI Kit correctly: the right components and rules, always matched to the version your app uses. One command sets it up.

> [!NOTE]
>
> AI support is in preview. We're expanding it with each release, and your feedback shapes what comes next.

## How it works

Once your project is set up, your agent has access to:

- **Design rules**: what applies to every screen, such as using design tokens, labelling form controls and protecting users from destructive actions.
- **Component guidance**: for each component, its props, what each variant is for, how its states behave and what it needs to be accessible. Your agent looks a component up before using it.

All of it comes from the **UI Kit** packages installed in your app. Your project only keeps a pointer and a little configuration, so when you upgrade, your agent follows the new version with no extra work.

If your agent reads documentation sites, it can also use this site's [llms.txt](/llms.txt).

## Set up

The quickest way is to let your agent do it. Paste this into your agent:

```text
Set up HV UI Kit for AI agents in this project:
1. Install the tools: npm install --save-dev @pentaho/uikit-tools
2. Run: npx --no-install uikit-tools init
3. Read the HV UI Kit design rules that AGENTS.md now points to and summarise them.
```

To do it yourself, install the tools and run `init`:

```sh npm2yarn
npm i -D @pentaho/uikit-tools
```

```sh
npx --no-install uikit-tools init
```

`init` sets up your project for every supported agent:

| File               | What `init` adds                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `AGENTS.md`        | A short UI Kit block that points your agent to the design rules in your installed UI Kit tools. The rest of the file stays yours. |
| `CLAUDE.md`        | An import of `AGENTS.md`, so Claude Code reads the same instructions.                                                             |
| `.vscode/mcp.json` | The `hv-uikit` MCP server for GitHub Copilot. Other servers are kept.                                                             |
| `.mcp.json`        | The `hv-uikit` MCP server for Claude Code. Other servers are kept.                                                                |

To set up only one agent, pass `--agents copilot` or `--agents claude`. Commit these files so your whole team shares the same setup, then start a new agent session. Running `init` again is safe: it only rewrites its own block and entries.

## Check your setup

Ask your agent:

```text
Answer from the HV UI Kit design rules and uikit-tools lookups, not from memory:
1. Which HvButton variant should a form's main action use?
2. How do you show a number in an HvBadge?
3. How should an HvDialog show its title?
```

A working setup answers: `primary`, one per form; set `showCount`; with `HvDialogTitle`, not plain text. If your agent answers from memory or invents props, check the setup and restart the session.

## Command line and MCP

The `uikit-tools` command line is the core. The `hv-uikit` MCP server is a thin layer over it: the same lookups, returning the same answers.

- **Your agent** calls the MCP tools on its own once it is connected. You don't run them.
- **You, your scripts and CI**, and agents without MCP, use the command line. Run it with `npx --no-install`, which uses the version installed in your project and never downloads another one.

| Task                                     | Command line                   | MCP tool          |
| ---------------------------------------- | ------------------------------ | ----------------- |
| Set up your project                      | `uikit-tools init [folder]`    | —                 |
| List the components                      | `uikit-tools components`       | `list_components` |
| Look up a component's guidance and props | `uikit-tools info <component>` | `get_component`   |
| List the design rules                    | `uikit-tools rules`            | `list_rules`      |
| Read a design rule                       | `uikit-tools rule <id>`        | `get_rule`        |
| Start the MCP server                     | `uikit-tools mcp`              | —                 |

Your agent starts the MCP server from the configuration `init` adds. It runs locally, only reads UI Kit's data and makes no network calls. Run `npx --no-install uikit-tools --help` to see every option.

### Look things up

```sh
npx --no-install uikit-tools info HvDialog
npx --no-install uikit-tools rule tokens/colors
```

These print the same text your agent gets from `get_component` and `get_rule`, so you can see exactly what it sees.

## Keep it current

Upgrade the UI Kit packages as usual. The design rules and component guidance come with the new versions, and your project's pointer still leads to them, so there is no need to run `init` again. Restart your agent's MCP server to pick up the change; the command line reads it right away.
